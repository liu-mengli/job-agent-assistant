## 二、关键发现

### 1. Q5 FAIL — 口语化导致检索完全失败

```
提问: "定时器那一堆参数都是啥意思，怎么设置？"
改写: ["Timer Setting 参数 说明", "Timer Setting 时间设定 参数", "Timer Setting 设定参数 方法"]
结果: Dense=15, BM25=0, 精排后全部低于阈值0.01 → passed=0 → 用户得不到任何回答
```

**根因**: 口语化改写虽然包含了"Timer Setting"，但改写词的整体语义向量与文档中 Timer Setting 章节的匹配度下降。对比正式提问改写「Timer Setting 设置方法 参数列表」的 rerank=0.80→通过，口语化的改写虽然看起来类似，但在 bge-m3 的向量空间中相似度降低了。

### 2. Q0 丢失"Run Page"关键上下文

```
正式: "Run Page 执行模式 On Line Off Line" → 精确定位Run Page章节
口语: "运行模式 类型 状态" → 丢失页面上下文，检索范围扩大到所有页面
```

虽然本次口语化Q0反而多返回了1条结果，但这是由于LLM相关性过滤在正式测试中更激进地过滤了噪声。长期来看丢失关键术语会降低检索精度。

### 3. BM25 命中下降

| | 正式 | 口语化 |
|---|:---:|:---:|
| BM25 总命中 | 10 | 7 |
| BM25 覆盖题数 | 6/10 | 5/10 |

口语化表达中英文术语使用更少（"定时器"而非"Timer Setting"），BM25 关键词匹配机会减少。

## 四、结论

**口语化提问的鲁棒性不够。** Q5 的完全失败说明当前管线对口语化表述的容错能力有限 —— 一旦改写后的 query 与文档术语的向量距离稍远，Reranker + 阈值就会形成双重阻断。

**改进方向**:
1. Q5这类情况应触发 fallback: 阈值过滤后为空时, 保留 Reranker top-1(当前已对LLM过滤做了fallback, 但阈值阶段没有)
2. Query改写时强化术语表引导: 用户说"定时器"→术语表提示这是"Timer Setting", 强制注入
